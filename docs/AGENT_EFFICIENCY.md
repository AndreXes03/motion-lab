# Focused agent workflow

Start with `npm run agent:context -- TOPIC` (setup, updates, feedback, live, controls, video). This prints a small file/test map without loading source or making model calls. Read the shared repository rules once; load only references relevant to the task.

1. Turn feedback into a short checklist with intended visual effect and acceptance evidence. Reuse the approved brief. Ask only when ambiguity would materially change the result.
2. Locate symbols with scoped `rg -n`, then read the relevant range. Do not dump entire source trees, minified bundles, tool registries, commit diffs or session memories. Keep raw API responses in scripts and return only relevant fields, failures and counts. Fetch changed-file names before selected diffs.
3. For a video revision, inspect the current scene controls and saved recipe first. Adjust supported parameters instead of rewriting the scene. Load only selected feedback cases that match the problem, never the complete memory archive. Record one concise case per meaningful outcome when consent is enabled.
4. Publish one coherent checkpoint per independent feedback item so users see progress. Run syntax/schema checks and inspect the changed shot. Reuse the same Studio and tab. Group coupled edits that cannot be meaningfully previewed separately.
5. After a fix, rerun the failing or affected test. Do not rerun unrelated suites or repeat checks already covered by the build. Run required complete gates once for the final candidate; broaden only for a concrete cross-system risk. Visual review remains required: a green test cannot establish visual quality.
6. For CI, read a compact run/job status; fetch only failed step logs when necessary. Do not repeatedly load complete workflow payloads. Cancel obsolete runs for the same PR, not other work.
7. Keep progress and handoffs short: changed files, completed/pending feedback, last meaningful validation, next action. Do not repeat the brief or every tool result.

These rules reduce avoidable context and repeated work. Actual token savings depend on the model and session; no fixed percentage is guaranteed.
