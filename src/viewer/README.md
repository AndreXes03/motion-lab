# Studio viewer

[main.js](main.js) builds the scene workspace: Scene, Motion, Compositing, Audio, Versions and Code, with a persistent viewer and timeline. [style.css](style.css) handles its layout. Desktop exposes the complete authoring workspace; mobile keeps essential controls usable in a simpler layout.

Properties uses the shared [control widgets](control-widget.js), the scene catalog and the agent-authored panels in [control-selections.json](../../project/control-selections.json). Scene contains Motion, Lens, Lights, Character, Graphics and Appearance controls. Compositing has its own workspace, derived from the same saved manifest. Scene advanced panels start closed; supported compositing groups open in their dedicated workspace. Search, category, selected-object and workspace filters expose supported tools without deleting values or existing animation tracks. The pure [workspace model](workspace-model.js) respects authored panel categories and never adds controls beyond the selected manifest. Compositing acts on the image and remains accessible when an object is selected. [control-presets.json](../../project/control-presets.json) supplies curated lighting/compositing profiles and optional scene-specific interpolation suggestions.

The [Motion panel](motion-panel.js) opens on the video's original movement. Native BAX keys use the renderer's exact interpolation and support source value/time/easing edits, including Bézier handles. Function-authored scenes expose actual evaluated samples as read-only curves. Retime is a separate view for a camera or object's progress inside its authored shot; an identity progress line is never presented as the original ease. Advanced parameter tracks retain independent rates. The [authored motion protocol](../../docs/AUTHORED_MOTION_PROTOCOL.md) shares bindings, units, easing ownership and validation between coding agents, editor and server. Code → Animation handoff copies this contract with current animation data; it is a focused handoff, not a full recipe import format.

[Preview quality](preview-quality.js) provides Auto, Balanced, Fast and Sharp. Auto responds to interaction and measured frame cost; Fast simplifies supported effects. This browser-local preference never enters saved parameters or export settings. Preview requests pass the transient `previewQuality` render option to the [runtime](../engine/runtime.js); final rendering uses its own dimensions, frame rate, temporal samples and full effects.

Run `npm run viewer` for the local Studio and its [API](../../scripts/studio-api.mjs). In browsers with canvas recording support, the published Studio can export browser-rendered 720p or 1080p video, PNG frames and JSON recipes, with versions stored in that browser. MP4 is offered when the browser supports its encoder; otherwise it offers WebM. Browser video uses the real-time Three.js/Canvas path. Cycles and prepared Mixed renders require the local app; choosing one in a recipe does not mean the public site ran it. [Renderer selection](../../docs/RENDERER_SELECTION.md) describes the separate strategy/capability contract; selecting an engine does not verify its availability or picture fidelity.

The [reference panel](reference-panel.js) keeps local media and notes. Follow the [scene-control authoring contract](../../docs/ADAPTIVE_CONTROLS.md) and [visual checks](../../docs/QUALITY-GATES.md) when extending the editor or adapting a film. A passing build or deterministic preview remains technical evidence, not creative approval.

The shell follows the public landing's charcoal/lime visual system with restrained glass surfaces. The [local Flaticon Uicons sprite](../../public/vendor/uicons/SOURCE.json) is shared through [studio-icons.js](studio-icons.js), with visible attribution. Motion and Code have independently resizable panels; keyboard navigation supports the vertical desktop and horizontal mobile workspace tabs. Preview quality remains separate from export.

Run `node scripts/test-workspace-model.mjs` to check scene routing, context filtering, custom manifests and immutability. Browser workflows are in `test-scene-tools-browser.mjs`, `test-workflow-browser.mjs` and `test-motion-interaction-browser.mjs`; these are separate from the build's engine contracts.

Easy / Pro changes only workspace presentation. Easy keeps source editing and the selected video controls; Pro exposes catalog selection, precision, Code and additional render actions. Hidden values/tracks remain intact. Selecting a workspace from Large preview reopens its panel.

The [viewport shading toolbar](viewport-toolbar.js) provides Final look, Without effects, Clay, Wireframe and Normals for adapters with mesh support. It uses a separate transient `previewReview` option, excluded from recipes and final video exports. Pure Canvas scenes do not advertise unsupported mesh modes. Preview PNG intentionally captures the selected display mode.

Render View pauses playback and refines a still frame at 1920 × 1080 (1280 × 720 on small screens), with full Three.js/Canvas effects. Edits first update at interactive resolution, then settle after a short debounce. Play restores the prior interactive mode. This is a full-resolution raster preview, not a Cycles/Redshift path-traced or temporally sampled export. Render mode never enters a recipe or persists across reload.
